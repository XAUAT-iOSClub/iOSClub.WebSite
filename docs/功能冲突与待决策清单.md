# 功能冲突与待决策清单

对应 [PRD v0.1](PRD-iOSClub-功能现状与冲突梳理.md)。检查日期 2026-10-25，源码基线 `0d44921`。

修复更新于 2026-10-25。C01 至 C05 已在本地修复，后端全套 390 项测试通过，尚未部署。实现变化、失败前证据、复验命令与兼容性见 [P0 修复与 TDD 验证记录](P0修复与TDD验证记录.md)。下文保留原基线的问题描述，C06 至 C30 仍待处理。

以下为源码静态检查结果，没有执行线上请求或运行攻击验证。P0 表示建议首先处理的身份、权限或会话问题，P1 表示关键业务闭环和数据可靠性问题，P2 表示兼容性、反馈与契约问题。优先级为本次建议，不是负责人已批准的排期。

## 1. 身份、权限与内容访问

### C01 · P0 · 干部备用登录不验证密码

操作条件为学生密码登录失败后进入备用路径。代码将 Password 当作 Staff 学号，将 UserId 当作干部姓名，匹配后签发令牌，不校验密码哈希。仅修改 Student 密码不能消除这条路径。

证据为 [AuthController.cs:68](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/AuthController.cs#L68) 和 [LoginService.cs:537](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Services/LoginService.cs#L537)。

建议关闭这条兼容路径，并为正式账号定义凭证。验收需证明仅知道姓名和学号无法登录，合法密码仍可登录。

### C02 · P0 · 常规干部接口绕过专用角色保护

部长和社长可进入 Staff/Create、Update、Delete。更新仓库直接写入 Identity，删除仓库直接移除 Staff。它们没有复用 Founder 专用变更接口中的禁止自改、合法身份和最后一位 Founder 保护。

证据为 [StaffController.cs:12](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/StaffController.cs#L12)、[StaffRepository.cs:270](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Repositories/StaffRepository.cs#L270)，对照 [UpdateRoleAsync:111](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Repositories/StaffRepository.cs#L111)。

验收需覆盖直接调用接口。部长不能将自己升级为 Founder，不能修改或删除 Founder。禁止通过换用接口绕过同一业务规则。

### C03 · P0 · 部门导入的 Founder 保护不覆盖传入名单

当前保护只检查目标部门原有名单。传入学号可从全局 Staff 找到其他部门或无部门的 Founder，然后覆盖其角色和部门。

证据为 [DepartmentImportService.cs:98](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Services/DepartmentImportService.cs#L98) 与 [同文件:137](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Services/DepartmentImportService.cs#L137)。

验收需覆盖传入其他部门 Founder、无部门 Founder 和回滚名单。所有写入路径均需拒绝不允许的角色变更，并保持原数据不变。

### C04 · P0 · Redis 会话失效没有终止受保护请求

JWT 中间件验证签名和有效期成功后建立身份。全局过滤器发现 Redis 中令牌无效时仅 return，没有设置拒绝结果。由此推导，已登出或被替换的 JWT 在到期前可能继续通过普通授权接口，与显式查询 Redis 的 SSO 接口产生不同结果。

证据为 [Program.cs:223](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Program.cs#L223) 和 [GlobalAuthorizationFilter.cs:61](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/IdentityModels/GlobalAuthorizationFilter.cs#L61)。

验收需在隔离环境保存旧令牌，登出后直接请求受保护接口，得到未认证响应。角色变更和密码重置的撤销范围还需产品确定。

### C05 · P0 · 匿名缓存清理可破坏会话

`GET /clean` 没有身份要求，会删除 token、refresh、user、oauth:auth 和刷新黑名单相关 Redis 键。项目没有为该入口配置全局授权兜底。生产网关是否另有限制未验证。

证据为 [CacheController.cs:16](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/CacheController.cs#L16) 和 [Program.cs:621](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Program.cs#L621)。

验收需证明匿名及普通成员不能清理会话。被授权操作也应明确影响范围，不能使用读取请求执行清理。

### C06 · P1 · 日志读写权限与管理入口不一致

前端按管理角色显示日志入口，后端 LogsController 只有 Authorize，任意登录角色可读取和清理日志。

证据为 [LogsController.cs:14](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/LogsController.cs#L14)、[cleanup:266](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/LogsController.cs#L266) 和 [Sidebar.vue:158](../frontend/src/components/Sidebar.vue#L158)。

建议将日志读取与清理分别列为管理权限。验收需直接使用 Member、Department 账号请求清理接口，不能仅检查菜单是否隐藏。

### C07 · P1 · 统计重置未要求登录

MonitoringController 无身份限制，包括重置数据统计的写操作。读取指标是否公开属于部署与产品决策，重置权限需要独立规定。

证据为 [MonitoringController.cs:118](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/MonitoringController.cs#L118)。

验收需证明匿名与非授权角色不能重置统计。运维人员按已确认权限执行重置后，界面明确反馈影响范围。

### C08 · P1 · 分类接口绕过文章可见性过滤

文章详情、搜索等入口使用职级和部门规则。公开分类文章接口直接查询分类下全部标题和路径。按分类名查询还会加载 Articles。这里确认的是受限标题和路径的暴露，不能据此声称正文已经泄露。

证据为 [CategoryController.cs:60](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/CategoryController.cs#L60)、[CategoryRepository.cs:199](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Repositories/CategoryRepository.cs#L199)、[按名称加载:82](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Repositories/CategoryRepository.cs#L82)，对照 [ArticleAccessPolicy.cs:36](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Repositories/ArticleAccessPolicy.cs#L36)。

验收需为匿名、普通成员、本部门和其他部门用户对照分类目录、搜索与详情结果。无权限文章不得出现在标题列表中。

## 2. 成员维护、备份与界面反馈

### C09 · P1 · 新增成员使用更新接口

新增分支调用 MemberManagement/update，该接口在学号不存在时返回失败。因此页面提供了当前接口无法完成的创建操作。

证据为 [MemberData.vue:510](../frontend/src/adminPages/MemberData.vue#L510) 和 [MemberManagementController.cs:84](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/MemberManagementController.cs#L84)。

需先决定是否支持管理员创建账号。若支持，验收需包含新增、再次查询、初始凭证及重复学号反馈。若不支持，移除新增入口。

### C10 · P1 · 编辑后按角色替换列表行

保存后使用 identity 查找首个同角色成员，而不是使用 userId。多个同角色成员存在时，前端可能替换错误行。此问题不能推断为后端更新了错误学号。

证据为 [MemberData.vue:506](../frontend/src/adminPages/MemberData.vue#L506)。

验收需在列表包含多个 Member 时编辑第二个成员。仅该学号对应行变化，刷新后与数据库读取结果一致。

### C11 · P1 · 已登录管理员导出仍读取旧令牌键

导出前读取 localStorage.Authorization，登录只保存 accessToken 和 refreshToken。正常登录没有旧键时，导出在调用接口前就报告未授权。

证据为 [Admin.vue:238](../frontend/src/adminPages/Admin.vue#L238) 与 [AuthService.ts:124](../frontend/src/services/AuthService.ts#L124)。

验收需从清空本地存储后的正常登录开始，直接导出文件，不依赖历史键。

### C12 · P1 · 完整备份的承诺超过实际覆盖范围

export-json 只填 Students、Departments、Presidents 和 Resources，没有填导入 DTO 支持的 Articles。分类、活动、参与者、客户端等也未列入导出结构。导入主动清空 Departments 内的 Staffs，因此无法恢复普通部门干部名单。合并导入也不等于空库完整还原。

证据为 [DataCentreController.cs:153](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/DataCentreController.cs#L153) 和 [DataCentreService.cs:173](../rearend/iOSClub.WebAPI/iOSClub.DataApi/Services/DataCentreService.cs#L173)。

验收需先明确备份实体和敏感字段范围，再使用隔离数据导出到空库恢复，核对实体数量、关系和关键字段。若定位为部分数据交换，界面与说明书必须使用该名称。

### C13 · P1 · 前端刷新和退出没有统一状态来源

通用请求刷新直接调用 AuthService，仅更新 localStorage。路由守卫却读取 Pinia 中的旧令牌，可能在请求刷新成功后仍将用户跳回登录。退出请求失败时 AuthService 不清理持久令牌，Store 已清内存并忽略失败，重新加载页面后又可能读回旧登录态。

证据为 [ApiService.ts:187](../frontend/src/services/ApiService.ts#L187)、[AuthService.ts:181](../frontend/src/services/AuthService.ts#L181)、[退出逻辑:89](../frontend/src/services/AuthService.ts#L89)、[Authorization.ts:31](../frontend/src/stores/Authorization.ts#L31) 和 [router.ts:261](../frontend/src/router.ts#L261)。

验收需覆盖自动刷新后继续导航，以及断网退出后重新加载。本地凭证始终清理，服务端撤销失败单独反馈。

### C14 · P1 · 统计请求失败显示固定数字

管理者概览统计失败时显示 128 名成员、42 名干部、24 个资源和 4 个部门。这些是代码中的示例值，不是真实统计结果。

证据为 [Centre.vue:367](../frontend/src/adminPages/Centre.vue#L367)。

验收需让统计请求失败，界面显示不可用或重试，不能把示例数或零值呈现为查询结果。

### C15 · P2 · 菜单权限和业务操作权限没有对齐

分类写操作只允许 Founder、President，但部长可进入相关后台页面。资源接口读取会进一步要求 Staff 为 Department 及以上，菜单又限 Minister，导致合法部员缺少入口。普通 Member 并不能因为控制器只标 Authorize 就读取资源。

证据为 [CategoryController.cs:70](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/CategoryController.cs#L70)、[ResourceControllers.cs:35](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/ResourceControllers.cs#L35)、[IsClubMember:272](../rearend/iOSClub.WebAPI/iOSClub.WebAPI/Controllers/ResourceControllers.cs#L272) 与 [Sidebar.vue:150](../frontend/src/components/Sidebar.vue#L150)。

验收需为每个角色检查菜单、直接导航、按钮和直接接口。确认只读用户的入口，不把菜单隐藏作为权限防线。

### C16 · P2 · 删除反馈和抹除入口承诺不一致

文章删除确认称永久删除，成功后却称移至废纸篓，当前未找到恢复入口。数据抹除按钮硬编码请求其他域名的 Admin/RemoveAllData，当前仓库未找到对应控制器。不能据此断言远端线上必然 404。

证据为 [ArticleManager.vue:217](../frontend/src/adminPages/Article/ArticleManager.vue#L217) 与 [Admin.vue:271](../frontend/src/adminPages/Admin.vue#L271)，后端声明范围见 [功能入口索引](功能入口索引.md)。

验收需统一文章删除与恢复文案。抹除功能需确认归属、授权和恢复前提，或者移除误导入口。本轮没有执行抹除请求。

## 4. 产品关系与运行待验事项

这些事项不能仅凭当前实现判断为 bug，应结合 [PRD 第 7.2 节](PRD-iOSClub-功能现状与冲突梳理.md#72-必须由负责人确定的规则) 评审。

| 事项 | 已观察到的实现 | 需要确定或验证的内容 |
| --- | --- | --- |
| 活动公开展示 | `/event` 是静态介绍，后台活动是独立数据库 | 是否联通，匿名登记页是否公开名称、时间、地点和开放状态 |
| 状态与登记 | 独立开关可打开非 Ongoing 活动，定时任务仍按时间推进 | 是否允许提前登记与补登，管理员手动回退后如何处理 |
| 文章作者权限 | Department 可维护符合可见性要求的文章 | 可见是否就代表可编辑、可删除，是否需要作者所有权 |
| 公开与 Member 文章 | 匿名读取可按 Member 等级参与判断 | Member 是阅读级别还是登录门槛 |
| 外部内容与内部内容 | 博客、工具来自外部，文章、资源来自本站 | 导航名称、运营职责和故障反馈如何区分 |
| 跨部门管理 | Minister 在多个控制器拥有全站操作权 | 是否限制部门数据范围，批量导出和导入是否采用同一范围 |
| 删除与账号关系 | 删除学生档案不必然删除 Staff，名单覆盖会删除 Staff 但保留 Student | 退社、毕业、撤职和注销的独立含义及账号处置 |
| 回滚范围 | 部门名单快照与资料非空合并同时存在 | 回滚是恢复名单、角色，还是完整档案，空字段能否还原 |
