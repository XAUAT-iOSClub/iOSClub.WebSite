# 财务模块使用与部署说明

> 对应 PRD：`财务系统PRD1.0.md`、`财务系统功能开发清单1.0.md`
> 接入方式：在现有官网中新增模块，不改动登录、现有业务表与现有接口。

## 一、入口与权限

- 后台入口：侧边栏「财务管理」→ `/Centre/Finance`。
- 允许角色：`Founder`、`President`、`Minister`（四类身份同权）。
- 无入口角色：`Department`、`Member`。前端路由守卫会跳转 `/access-denied`，
  后端统一 `[Authorize(Roles = "Founder,President,Minister")]` 校验。
- 财务模块不登录、不新建账号、不新增身份表；操作人、角色、IP、User-Agent 全部取自
  网站现有 JWT 与请求上下文。

## 二、页面

| 路由 | 页面 | 主要能力 |
|------|------|----------|
| `/Centre/Finance` | 经费看板 | 年度经费、已用、在途、剩余、预警、最近流水、设置年度经费 |
| `/Centre/Finance/Invoices` | 发票库 | 上传自动识别、人工录入、人工确认、删除 |
| `/Centre/Finance/Materials` | 报销材料 | 筛选、新建、批量导出、批量删除、恢复 |
| `/Centre/Finance/Materials/:id` | 材料详情 | 活动信息、发票明细、生成表单、确认/撤销、日志 |
| `/Centre/Finance/Flows` | 经费流水 | 按学年、类型、时间、活动筛选 |
| `/Centre/Finance/Logs` | 操作日志 | 组合查询、详情抽屉、导出 CSV |

## 三、关键口径

### 金额

- 数据库以「分」（`long`）存储，所有计算为整数运算。
- 接口边界与页面展示为「元」（`decimal`，最多两位小数）。
- 人民币大写由 `FinanceMoney.ToChineseUpper` 生成，用于表单合计栏。

### 经费

```
D = max(0, C − S)      C：材料已确认发票合计；S：材料填写的活动经费
R = 年度经费 − ΣD      R：剩余经费
```

- 只有「已报销」材料参与扣减；「待报销」只计入“在途金额”。
- 开销小于活动经费时差额不退不补，`D = 0`。
- 每次确认报销写一条扣减流水；撤销时原扣减流水置为 `voided`，并写一条回滚流水。
- 学年按 9 月 1 日至次年 8 月 31 日划分；历史学年只读，不自动结转。

### 材料状态

```
（新建）──生成表单──▶ 待报销 ──确认已报销──▶ 已报销
                        ▲                      │
                        └──────撤销报销─────────┘
```

- 待报销：可编辑、可归集/解除发票、可生成与导出。
- 已报销：字段锁定，参与扣减；需先撤销才能修改。
- 删除：软删除，30 天内可恢复；已报销材料需先撤销。

### 学年切换

- 学年按中国标准时间判断，**9 月 1 日 00:00 自动进入新学年**（不依赖服务器时区，Docker 用 UTC 也不会错）。
- 新学年没有年度经费记录，看板显示 0，需要重新设置该学年的年度经费。
- 历史学年只读，不自动结转；旧材料仍保留原学年，确认/撤销时会写入原学年的流水。
- 材料创建或修改活动时间时，按活动时间所属学年归档；活动时间为空时按创建时间归档。

### 发票

- 上传格式：jpg / jpeg / png / webp / bmp / docx / pdf，单个 ≤10MB。
- 前端逐张上传，避免超过网站全局 10MB 请求上限。
- 同一材料内「发票代码 + 号码」重复 → 阻断；跨材料重复 → 提示占用。
- 开票日期晚于当天 → 阻断；金额/行金额差异、抬头不一致、超出活动时间 ±30 天 → 提示。
- 识别失败保留原件并转手工录入，不阻断流程。

## 四、配置

配置节：`Finance`，环境变量使用双下划线（如 `Finance__StorageRoot`）。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `Finance__StorageRoot` | 内容根目录/`App_Data/finance` | 发票原件、生成文档、模板的落盘根目录 |
| `Finance__ClubName` | `西安建筑科技大学 iOS Club` | 购买方抬头校验与表单默认值 |
| `Finance__LowConfidenceThreshold` | `0.8` | 低于该值的字段前端标黄 |
| `Finance__OcrEndpoint` | 空 | 可选的外部 OCR 服务地址；为空时图片/扫描件转手工录入 |
| `Finance__OcrApiKey` | 空 | 外部 OCR 的 Bearer Token |
| `Finance__PdfConverterPath` | 空 | 可选，LibreOffice/soffice 可执行文件路径；配置后可导出 PDF |
| `Finance__RecognitionTimeoutSeconds` | `15` | 单张识别超时 |
| `Finance__MaxFileSizeMb` | `10` | 单个文件上限 |
| `Finance__MaxFilesPerUpload` | `20` | 单次上传数量上限 |

### 外部 OCR 约定

`Finance__OcrEndpoint` 接收 `multipart/form-data`，文件字段名为 `file`。
返回 JSON（也兼容 `{ "data": { ... } }`）：

```json
{
  "type": "增值税电子普通发票",
  "code": "044001900111",
  "number": "12345678",
  "issueDate": "2026-10-20",
  "buyer": "西安建筑科技大学 iOS Club",
  "seller": "西安某某科技有限公司",
  "item": "活动物料",
  "qty": 2,
  "price": 150.00,
  "unit": "批",
  "amount": 300.00,
  "tax": 18.00,
  "total": 318.00,
  "confidence": { "number": 0.99, "total": 0.92 }
}
```

未配置 OCR 时：

- `.docx` 会解析 `word/document.xml` 文本并抽取字段；
- 带文本层的 PDF 会解析内容流文本；
- 只含图片的 `.docx` 会抽取 `word/media/*` 图片；
- 只含图片的 PDF 会抽取其中的 JPEG 图片；
- 抽出的图片会逐张提交到 `Finance__OcrEndpoint`，由外部 OCR 返回字段；
- 未配置 OCR 服务时，以上图片型文件识别失败，保留原件并转手工录入（符合 PRD 1.7）。

因此图片型发票要自动识别，必须先配置一个可用的 OCR 服务；后端只负责抽取图片和回填字段。

### 本地 / 远端 PaddleOCR

PaddleOCR 作为独立服务放在 `tools/paddle-ocr/`，不装进 WebAPI：

- 本地安装的 Python 包、模型、虚拟环境不会随 Git 提交；
- 远端服务器需要重新 `docker compose up -d --build`，或重新 `pip install -r requirements.txt`；
- 推荐用 Docker；Dockerfile 在构建阶段把 PP-OCRv4 模型打入镜像，运行时不再下载；
- 模型下载失败时镜像构建直接失败，避免部署后“服务活着但不能识别”；
- 容器自带 healthcheck，部署后用真实发票跑 `smoke-test.ps1` / `smoke-test.sh` 才算验证完成；
- 版本固定为 PaddlePaddle 3.0.0 + PaddleOCR 3.7.0，oneDNN 开启；
- 后端配置：

```text
Finance__OcrEndpoint=http://127.0.0.1:5099/ocr
Finance__RecognitionTimeoutSeconds=180
# 同一 Docker 网络内可用 http://finance-ocr:5099/ocr
```

详细步骤见 `tools/paddle-ocr/README.md`。模型目录、虚拟环境和缓存已加入 `.gitignore`。

### PDF 导出

配置 `Finance__PdfConverterPath` 指向 LibreOffice 的 `soffice` 可执行文件后，
`GET /Finance/materials/{id}/export?format=pdf` 会调用：

```
soffice --headless --convert-to pdf --outdir <临时目录> <docx>
```

未配置时接口返回明确提示，不影响 docx 导出。

## 五、数据库

- 新增迁移：`20261105145943_AddFinanceSystem`。
- 新增 6 张表：`finance_material`、`finance_invoice`、`finance_account`、
  `finance_flow`、`finance_log`、`finance_template`。
- 只建新表、新索引，不修改现有表与字段。
- 应用启动时沿用现有 `MigrateAsync` 自动应用迁移；SQLite 与 PostgreSQL 都已验证建表。
- 主键：
  - 材料：`CL-YYYY-NNNN`（由系统生成，并发撞号时自动重试）。
  - 发票/学年/模板：GUID 字符串。
  - 流水/日志：GUID 字符串，避免不同数据库自增语义差异。

## 六、文件存储

```
App_Data/finance/
├── invoices/YYYY/MM/<guid>.<ext>      # 发票原件
├── materials/<材料编号>/<guid>.docx    # 生成表单
└── templates/<apply|reimburse>/...    # 上传模板
```

- 文件名统一重命名，保留原始文件名到数据库。
- 存储目录不在 Web 根目录下；读取必须经过 `/Finance/invoices/{id}/file` 并携带 token。
- 生产环境请把该目录纳入备份，并确保运行账号有读写权限、目录不可执行。

## 八、内置学校模板

模板管理页已取消。系统内置两份学校固定模板，随程序发布：

- 经费报销单：`FinanceTemplates/reimburse.docx`
- 社团经费申请表：`FinanceTemplates/apply.docx`

生成时优先使用这两份内置模板，按“社团名称 / 报销人 / 活动主题 / 支出项目 / 合计（小写）/
合计（大写）”等表头和标签定位单元格。只修改文本，不改变字体、行高、列宽、合并单元格与边框。

- 经费报销单：社团信息、报销人姓名/学号/电话、10 行报销清单、合计金额；
- 社团经费申请表：申请单位/承办单位、活动信息、活动经费一行、合计小写/大写；
- 单价按含税金额 / 数量折算，保证 `单价 × 数量 = 金额`；
- 导出文件不追加“导出时间 / 操作人 / 材料编号”页脚；
- 签字、盖章栏保持空白，由线下完成。

如果以后更换模板版式，需要同时更新 `FinanceTemplates` 下的 docx 和字段映射代码，不能只替换文件。

## 十、运维注意事项

- 日志只追加，不提供修改与删除接口；建议按年归档数据库备份，保留 ≥3 年。
- 发票与材料原件建议保留 ≥5 年；备份 `Finance__StorageRoot` 目录。
- 生产环境建议将 `Finance__StorageRoot` 指向独立数据盘，并限制目录执行权限。
- 数据库账号无需 DDL 权限以外的额外权限；迁移由应用启动时执行。
